Cyberry Potter 学习指南

从零啃穿一块跑 CNN 的 STM32 —— 按数据流顺序，逐层击穿

前言

这是一个「麻雀虽小、五脏俱全」的项目。你手里拿着的，是在一块 72MHz Cortex-M3、只有 20KB SRAM 的芯片上跑卷积神经网络的完整实现。 没有什么 NPU，没有什么 TFLite Micro，就是纯 C 实现的 NNOM + 一个自训练的 1D-CNN。

这份指南的核心理念：

  • 不是按文件读，而是按数据流读 — IMU 数据从哪来、经过什么变换、最终怎么变成红外信号
  • 不是泛泛讲概念，每个阶段都有可执行的练习
  • 读懂 20% 的核心代码，就能理解 80% 的系统
💡 建议的学习方式 打开 Keil 工程 + 这份指南，边看边搜。遇到不懂的外设寄存器，直接查 STM32F103 参考手册。 每个阶段控制在 1-2 小时内完成。

第二阶段 · MPU6050 驱动与采样

驱动层次

MPU6050 的代码分三层，从底到高：

┌──────────────────────────┐
│  IMU_Get_Data(index)     │  ← 最上层：每中断读一个采样点
│  IMU.c                   │     存入 IMU.acc[i][3] / IMU.gyro[i][3]
├──────────────────────────┤
│  MPU6050 DMP (eMPL/)     │  ← 中间层：姿态解算引擎
│  inv_mpu.c               │     FIFO 读取 → 四元数 → 欧拉角
├──────────────────────────┤
│  IIC.c                   │  ← 底层：软件模拟 I2C
│  PB6=SCL, PB7=SDA        │     Start/Stop/ACK/Read/Write
└──────────────────────────┘
为什么用 DMP？ DMP（Digital Motion Processor）是 MPU6050 内部的硬件姿态引擎。它把 6 轴原始数据融合成四元数， 再转成欧拉角（Roll/Pitch/Yaw）。如果不使用 DMP，你就得自己写卡尔曼滤波或互补滤波。 DMP 减少了 MCU 的计算负担，这对只有 72MHz 的 F103 来说很重要。

中断驱动的采样环

这是整个系统最关键的中断服务函数，在 CyberryPotter.c 中：

void EXTI9_5_IRQHandler(void)
{
    static uint8_t i = 0;
    if(EXTI_GetITStatus(EXTI_Line5) == SET) {  // MPU6050 INT → PB5
        IMU_Get_Data(i);    // 读 DMP FIFO，存到 IMU.acc[i]/IMU.gyro[i]
        i++;
        if(i >= IMU_SEQUENCE_LENGTH_MAX) {  // 满了 150 个点
            i = 0;
            IMU.Sample_Stop();  // IMU.status → IMU_Sampled
            // 如果是数据采集模式，打印原始数据到串口
        }
        EXTI_ClearITPendingBit(EXTI_Line5);
    }
}
问题答案
为什么是 EXTI Line5？MPU6050 的 INT 引脚连到 STM32 的 PB5，对应 EXTI Line5。MPU6050 DMP 每完成一次数据融合就产生一个脉冲
DMP 输出频率是多少？MPU6050 配置为 200Hz（由 DMP 固件设定），所以每 5ms 触发一次中断
为什么是 150 个点？IMU_SEQUENCE_LENGTH_MAX = 150，配合 200Hz = 750ms 的采样窗口。实际上 IMU_SAMPLING_TIME_MS 定义为 1500ms。两处为何不一致？查看原代码逻辑，EXTI 中断以 DMP 200Hz 触发，150 点=750ms，而 1500ms 是定时器超时保护
i 用 static 有什么问题吗？有！如果采样中途被打断，static i 会保留旧值。但这里中断优先级固定，且采样时禁用了 EXTI0（按键），所以实际上安全

数据结构 IMU_t

理解这个结构体，就理解了整个数据缓冲区的设计：

typedef struct IMU_t {
    eIMU_STATUS status;                              // Idle / Sampling / Sampled
    void (*Sample_Start)(void);                       // 开始采样（清零计数器等）
    void (*Sample_Stop)(void);                        // 结束采样（置状态 + 打印数据）
    float acc[IMU_SEQUENCE_LENGTH_MAX][3];     // 150 × 3 = 1800 字节（float×4 = 7200B）
    float gyro[IMU_SEQUENCE_LENGTH_MAX][3];    // 150 × 3 = 1800 字节
} IMU_t;
extern struct IMU_t IMU;  // 全局唯一实例
内存开销计算 acc: 150 × 3 × 4 bytes = 1800 字节
gyro: 150 × 3 × 4 bytes = 1800 字节
合计约 3.6KB，占 STM32F103C8T6 总 SRAM（20KB）的 18%。
加上 NNOM 模型（约 10KB 静态缓冲），只剩约 6KB 给栈和全局变量。
这就是为什么不能在函数内部开大数组——栈空间非常紧张。

时序与窗口设计

时间轴 →
  ═══0ms═══════════════════════════════════750ms════════800ms═══

  [按键按下]                               [最后一个中断]   [推理]
  EXTI_Line0 触发                         EXTI_Line5      main()
  → IMU.Sample_Start()                    → IMU_Sampled   → model_get
  → i=0, status=Sampling                                   _output()
       │
       ├── EXTI Line5 × 150 次 ──────────────▶
       │   IMU_Get_Data(0) ... IMU_Get_Data(149)
       │   每次填充 acc[i][AccX/Y/Z], gyro[i][Roll/Pitch/Yaw]
       │
       ▼
  IMU.status = IMU_Sampled  → 主循环检测到 → 运行推理

为什么选 150 点 × 200Hz？

  • 200Hz 采样足够捕获人体手势的运动频率（手部运动主频一般 <20Hz）
  • 750ms 窗口够长覆盖一个完整手势（挥手画圈大约 500-800ms）
  • 150 点 × 6 维 = 900 个值，1D-CNN 刚好能消化
⚠️ 静止校准 上电后 1 秒内法棒必须保持静止。这段时间 DMP 在自动校准陀螺仪零偏。 如果这 1 秒内移动了，后续所有姿态角都会有偏移，识别率会大打折扣。 这部分逻辑在 DMP 固件内部，不在用户代码中。

第三阶段 · NNOM 框架入门

NNOM（Neural Network on Microcontroller）是一个纯 ANSI C 实现的神经网络推理框架。 它不需要动态内存分配、不需要操作系统、不需要文件系统。 只需要一个数组和几个函数调用。

NNOM 的基本使用模式

// 1. 分配静态内存（可选，10KB 足够本项目）
uint8_t static_buf[1024 * 10];
nnom_set_static_buf(static_buf, sizeof(static_buf));

// 2. 从 weights.h 创建模型（模型结构和权重在编译期确定）
nnom_model_t *model = nnom_model_create();

// 3. 填数据到输入缓冲区
for(int i=0; i<INPUT_SIZE; i++)
    nnom_input_data[i] = (int8_t)round(raw_data[i] * scale);

// 4. 执行推理
model_run(model);

// 5. 读取输出（单次调用后 nnom_output_data 已填充）
int result = argmax(nnom_output_data, 13);

你需要知道的 NNOM 全局变量（在 weights.h 或 params.h 中声明）：

变量类型含义
nnom_input_dataint8_t*输入缓冲区指针，由 NNOM 管理
nnom_output_dataint8_t*输出缓冲区指针，13 个 int8_t 值
INPUT_1_OUTPUT_DEC#define量化的小数位数，计算 scale = 2^DEC

模型加载

nnom_model_create() 是一个看起来很简单的函数，但它背后读的是 weights.h 里生成的结构体。 看 weights.h 内部（不用深究细节）：

// weights.h — 由 NNOM 脚本自动生成，不要手动修改
static int8_t conv1_w[] = { ... };        // 第一层卷积权重
static int32_t conv1_b[] = { ... };       // 第一层偏置
static int8_t dense_w[] = { ... };        // 全连接层权重
// ... 更多层
nnom_model_t nnom_model = { ... };       // 模型结构描述

调用 nnom_model_create() 时，NNOM 会：

  1. 解析 nnom_model 结构，知道有几层、每层是什么类型
  2. 计算每层需要的内存，从 static_buf 中分配
  3. 初始化各层的权重指针，指向 weights.h 中的静态数组

数据喂入与量化

这是 model_feed_data() — 项目中最重要的数据变换函数：

#define QUANTIFICATION_SCALE (pow(2, INPUT_1_OUTPUT_DEC))

void model_feed_data(void)
{
    const double scale = QUANTIFICATION_SCALE;
    for(int i = 0; i < IMU_SEQUENCE_LENGTH_MAX; i++) {
        // 只喂陀螺仪 3 轴：Roll, Pitch, Yaw
        nnom_input_data[i*3  ] = (int8_t)round(IMU.gyro[i][Roll]  * scale);
        nnom_input_data[i*3+1] = (int8_t)round(IMU.gyro[i][Pitch] * scale);
        nnom_input_data[i*3+2] = (int8_t)round(IMU.gyro[i][Yaw]   * scale);
    }
}
步骤含义
IMU.gyro[i][Roll]第 i 个采样点的 Roll 角（弧度），DMP 已解算好
* scale放大到 int8 范围。例如 DEC=6 → scale=64，1 弧度 → 64 → int8 存为 64
(int8_t)round(...)四舍五入量化，丢掉小数。浮点 1.234 弧度 → int8 = 79
nnom_input_data[i*3+...]按 [点0_Roll, 点0_Pitch, 点0_Yaw, 点1_Roll, ...] 顺序排列
最终形状：[150, 3] → [450] 的一维数组
💡 为什么只用陀螺仪不用加速度？ 手势识别关注的是旋转轨迹（角速度积分→角度），而加速度反映的是线运动。 画圆圈这个动作，陀螺仪的角度变化模式比加速度更加区分度高。 如果识别「上下挥动」这种线性手势，6 轴模式可能更好——这就是为什么项目提供了两种模式。

前向推理 model_run

model_run(model) 一行调用，背后是完整的 CNN 前向传播。 对本项目而言，模型做的是： 

输入 [450] int8
    │
    ▼ Reshape → [150, 3]
1D Conv(3→8, kernel=3, stride=1, padding=same)
    │ ReLU
    ▼ [150, 8]
MaxPooling(pool=2, stride=2)
    │
    ▼ [75, 8]
1D Conv(8→16, kernel=3) → ReLU → MaxPooling
    │
    ▼ [37, 16]
Flatten → [592]
    │
    ▼ Dense(592 → 13)
Softmax → [13] int8
    │
    ▼ nnom_output_data[0..12]
模型压缩要点 1D CNN 比 2D CNN 小得多，因为卷积核是 1D 的（3×通道数 而不是 3×3×通道数）。 输入维度 [150,3] 也非常小。加上全程 int8 量化，模型总大小 ≈ 20KB， 这就是为什么能在 STM32F103 上跑。

输出解码 — model_get_output()

#define OUPUT_THRESHOLD 63  // 127 的一半，低于此值视为不可识别

Model_Output_t model_get_output(void)
{
    model_feed_data();        // 步骤 1: 量化喂数据
    model_run(model);           // 步骤 2: 前向推理

    int8_t max_output = -128;
    int ret = 0;
    for(int i = 0; i < 13; i++) {      // 步骤 3: argmax
        if(nnom_output_data[i] >= max_output) {
            max_output = nnom_output_data[i];
            ret = i;
        }
    }
    if(max_output < OUPUT_THRESHOLD || ret == NoMotion)  // 步骤 4: 阈值过滤
        ret = Unrecognized;

    return ret;  // -1=Unrecognized, 0~12=各类手势
}

为什么 int8 输出值的阈值是 63？

Softmax 输出归一化到 int8 范围 [-128, 127]。如果 13 个类别的概率全相等，每个 ≈ 127/13 ≈ 10。 只有当某个类的置信度明显高于随机水平（>63，即 127 的一半），才认为有效。 小于 63 说明模型对任何类别都没把握 → 输出 Unrecognized。

    Keras 1D-CNN 模型结构

    虽然训练源码不在项目中，但从 weights.h 和 NNOM 结构体可以反推模型架构：

    # 推测的 Keras 模型（基于 NNOM 模型结构反推）
model = Sequential([
    # 输入: (150, 3) — 150 个采样点 × 3 轴陀螺仪
    Conv1D(8, 3, padding='same', input_shape=(150, 3)),
    ReLU(),
    MaxPooling1D(2),           # → (75, 8)

    Conv1D(16, 3, padding='same'),
    ReLU(),
    MaxPooling1D(2),           # → (37, 16)

    Flatten(),                     # → (592)
    Dense(13, activation='softmax') # → 13 分类输出
])
    1D-CNN 为什么适用？ 手势数据是时序序列——150 个时间点 × 3 个通道（Roll/Pitch/Yaw）。 1D 卷积在时间轴上滑动，捕捉局部的运动模式（比如「上升→下降→上升」的三连击）。 这本质上和语音识别、心电图分类是一类问题。

    Module 函数表模式

    这是一种经典的嵌入式设计模式 — 用结构体封装多态行为：

    typedef struct Module_t {
    eModule_Type Type;                       // 当前激活的模块类型
    void (*Mode0_Handler)(void);           // 函数指针：模式 0 的处理
    void (*Mode1_Handler)(void);           // 函数指针：模式 1 的处理
} Module_t;

    在 Module_Init() 中，根据 Module.Type 的值，将 Mode0_Handler 和 Mode1_Handler 指向不同模块的处理函数。调用时只需要：

    Module.Mode0_Handler();  // 无论是红外发射还是 LED 闪烁，调用方不需要知道细节

    这就是 策略模式 在 C 语言中的实现。优点： 新增功能模块只需写一个新的 moduleX.c，在 Module_Init() 中加一个 case， main 循环完全不需要改动。

    红外协议与编码 — module0 详解

    module0.c 是最核心的模块，实现红外遥控功能。它的架构也很清晰：

    module0.c 内部组件：

  model_names[]    → 模型输出索引 → 手势名称映射表（调试用）
  model_indices[]  → 模型输出索引 → 红外信号索引映射表

  Mode0_Handler → handle_ir_signal(0) → IR_Send_Pack()
                                      → Uart_Send() 发送到红外子板
  Mode1_Handler → handle_ir_signal(1) → IR_Learn_Pack()
                                      → Uart_Send() 发送学习指令到红外子板

    红外子板（独立 STM8 MCU）：

    • 通过 UART2（PA2/PA3）与主控通信
    • 收到发射指令 → 调制 38KHz 载波 → 驱动 IR LED 发射 NEC 协议红外信号
    • 收到学习指令 → VS1838B 接收外部遥控器信号 → 解码存储 → 回传编码数据给主控
    子板通信协议 由 new_study_IR.c 和 protocol.c 实现，通过 UART2 发送特定格式的二进制数据包。 电机子板（Module 5）也使用同一子板通过 SPI1 通信。

    系统模式切换

    typedef enum eSystem_Mode {
    SYSTEM_MODE_0 = 0,   // 默认：红外发射模式
    SYSTEM_MODE_1 = 1,   // 红外学习模式
    SYSTEM_MODE_2 = 2    // 激光模式（可选，需 LASER_ENABLE）
} eSystem_Mode;

    长按 KEY0 → Cyberry_Potter_System_Status_Update() → 循环切换：

    MODE_0 → MODE_1 → (MODE_2, 可选) → MODE_0 → ...

    切换后，主循环依旧调用相同的 Module.Mode0_Handler()/Module.Mode1_Handler()， 但模块内部的 handle_ir_signal() 会根据 mode 参数（来自系统模式） 分发到红外发射或红外学习逻辑。

    常见踩坑记录

    坑 1：MPU6050 初始化卡死

    DMP 初始化需要约 200ms。如果 I2C 总线有干扰或 MPU6050 焊接不良，mpu_init() 会无限等待。
    解决：检查 I2C 上拉电阻（4.7kΩ）、用示波器看 SCL/SDA 波形。

    坑 2：编译报 "not enough space"

    STM32F103C8T6 只有 64KB Flash。确保 Keil → Options → Target → IROM1 设为 0x08000000, 0x10000。
    如果还是不够，考虑用 STM32F103RCT6（256KB Flash）或裁剪模型。

    坑 3：识别率骤降

    上电后 1 秒内移动了法棒 → DMP 校准失败 → 姿态角偏移 → 识别率下降。
    解决：上电时保持法棒绝对静止至少 2 秒。

    坑 4：串口乱码

    检查波特率是否为 115200、数据位 8、停止位 1、无校验。
    如果中文乱码，检查上位机编码是否为 UTF-8。

    坑 5：weights.h 替换后程序 crash

    新训练的模型结构和旧的 model_feed_data() 不一致导致。
    检查：输入维度、输出类别数、量化参数是否匹配。
